
=== LOG ATTRIBUTES INTERPRETATION GUIDE ===

Log attributes provide statistical metadata about the event log,
offering a high-level overview before detailed process mining.

OUTPUT FORMAT:
--------------
Each line describes one attribute:
"attribute_name  empty: N values: (value1; freq. X) (value2; freq. Y) ..."

For timestamp attributes:
"attribute_name  empty: N  quantiles: {0.0: Timestamp(...), 0.25: ..., 0.5: ..., 0.75: ..., 1.0: ...}"

EXAMPLE OUTPUT:
"activity  empty: 0 values: (Submit; freq. 1000) (Review; freq. 850) (Approve; freq. 500)
case:region  empty: 0 values: (North; freq. 5000) (South; freq. 3000)
resource  empty: 0 values: (John; freq. 2000) (Mary; freq. 1500)
time:timestamp  empty: 0  quantiles: {0.0: Timestamp('2024-01-01'), 0.5: Timestamp('2024-06-15'), 1.0: Timestamp('2024-12-31')}"

READING THE OUTPUT:

1. ATTRIBUTE NAME:
   - 'activity' or 'concept:name': The activity/event type
   - 'case:XXX': Case-level attributes
   - 'resource': Who performed the activity
   - 'time' or 'time:timestamp': Temporal information

2. EMPTY COUNT:
   - Number of events missing this attribute
   - 0 means complete data

3. VALUES (categorical):
   - Lists unique values with frequencies
   - Format: (value; freq. count)
   - Sorted by frequency (most common first)

4. QUANTILES (temporal):
   - 0.0: Earliest timestamp (min)
   - 0.25: First quartile
   - 0.5: Median timestamp
   - 0.75: Third quartile
   - 1.0: Latest timestamp (max)

USE FOR:
- Initial log exploration
- Data quality assessment
- Understanding process scope
- Identifying filtering needs
- Resource analysis

IMPLICATIONS FOR MODELING:
- High activity frequencies: Core process activities
- Low frequencies: Exceptions or edge cases
- Many resources: Consider organizational perspective
- Wide time range: Look for temporal patterns
