IDEAL Process Model

Process overview and purpose
- Purpose: A streamlined, well-governed hiring process that ensures consistent sequencing, minimizes rescinded offers, and improves throughput while preserving rigorous evaluation.
- Core improvement: Enforce a single, synchronized decision point where all required evaluations and checks are completed before issuing Make Job Offer.

Key stakeholders and roles involved
- Online System: Application intake and notifications; standardized templates for status updates.
- Front Desk: Centralized interview scheduling and candidate coordination.
- HR staff (HR-pro): Owns Telephonic Screening, Screening Interview, initiates and reviews Background Check; coordinates any Extensive Background Check requests.
- Coding Interviewer: Conducts Coding Interview and track-specific technical interviews (Frontend, Backend, ML).
- Panel: HR-pro and Senior Partner for Behavioral Interview (panel configuration remains, but scheduling is optimized).
- deepResearch Inc. (external vendor): Executes Extensive Background Check when required; engaged early enough to avoid blocking the final decision.

Detailed step-by-step process flow

1) Start conditions and triggers
- Trigger: Candidate completes Hand In Job Application via the Online System.
- Immediate actions: Automated acknowledgment sent; candidate data prepared for screening.

2) Initial screening stage gate
- Activity: Telephonic Screening (HR-pro)
  - Decision: Pass → proceed; Fail → Application Rejected (end).
- Activity: Screening Interview (HR-pro)
  - Decision: Pass → proceed; Fail → Application Rejected (end).

3) Early verification and technical pipeline (controlled parallelism)
- Activity: Background Check (baseline)
  - Initiation: Start as soon as the candidate passes the Screening Interview to overlap with technical evaluations and compress cycle time.
  - SLA: Complete by or before the final decision point; results available to the decision board.
- Technical evaluation (inclusive per role, but with clear completion criteria)
  - Activity: Coding Interview (Coding Interviewer).
  - Activities: Track-specific interviews as applicable (Frontend Interview, Backend Interview, ML Interview). The set is defined by the requisition/role profile.
  - Control logic: Inclusive gateway selects all required tracks for the role. These can be scheduled in any order. All selected tracks must be completed.
  - Synchronization: A hard join ensures that all required technical interviews are completed before proceeding.

4) Behavioral assessment
- Activity: Behavioral Interview (panel: HR-pro and Senior Partner)
  - Scheduling optimization: Use defined panel time blocks to reduce wait time, while maintaining the panel composition.
  - Decision: Pass → candidate eligible for final consideration; Fail → Application Rejected (end).

5) Deep-dive verification (risk-based, but ordered before decision)
- Activity: Extensive Background Check (deepResearch Inc.)

- Background Check: Clear vs Flag; Flag either triggers Extensive Background Check or leads to Application Rejected based on policy.

- Final decision gate: Offer only if all conditions are satisfied; else rejection.

Parallel activities and synchronization points
- Controlled parallelism:
  - Background Check runs in parallel with technical interviews to reduce cycle time.
- Mandatory synchronization:
  - Join of all required technical interviews.
  - Join of all verification checks (Background Check and, if applicable, Extensive Background Check) and Behavioral Interview before the final decision.
- Result: Eliminates late-stage reversals and reduces idle time.
