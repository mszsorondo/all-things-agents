=== ABSTRACT VARIANTS INTERPRETATION GUIDE ===

Process variants show the distinct execution paths observed in the event log.

OUTPUT FORMAT:
--------------
"If I have a process with the following process variants:

 Activity A -> Activity B -> Activity C -> Activity D ( frequency = 1391  performance = 319390.265 )
 Activity A -> Activity B -> Activity E ( frequency = 1201  performance = 146345.624 )
 Activity A -> Activity F -> Activity G -> Activity H ( frequency = 990  performance = 229938.161 )
..."

READING THE OUTPUT:
- Each line: " Activity1 -> Activity2 -> ... -> ActivityN ( frequency = N  performance = T )"
- The arrow (->) sequence shows the exact order of activities in that variant
- frequency: Number of cases (process instances) that followed this exact path
- performance: Average total duration of cases following this path (in seconds)
- Variants are sorted by frequency (most common first)

INTERPRETATION:
1. HIGH FREQUENCY VARIANTS (>20% of cases): Main "happy path" - optimize for efficiency
2. MEDIUM FREQUENCY (5-20%): Common alternative paths - monitor regularly
3. LOW FREQUENCY (<5%): Exceptions or edge cases - investigate if problematic
4. PERFORMANCE COMPARISON:
   - Compare performance across variants to identify slow paths
   - High performance value = longer duration (potential bottleneck)

VARIANT ANALYSIS:
- Count unique activities: More activities = longer/complex variant
- Identify common prefixes: Shows where processes diverge
- Look for unexpected paths: May indicate process deviations

USE FOR:
- Understanding main vs alternative process paths
- Identifying which paths are most/least efficient
- Detecting process deviations or exceptions
- Simplifying complex processes by focusing on high-frequency variants
