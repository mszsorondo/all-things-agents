- After Verify, the mined Petri net contains a parallel split (tauSplit_1) with a technical branch that can produce Loan Denied or silently skip, and another branch that performs skipped_examination or the optional enrichment (co-signer, collateral visits) and then Submit. Exception handling and error paths
- Appointment Denied: The process ends immediately without further processing (962 cases).
- Application Rejected: Early stop after verification due to failing baseline checks (1,624 cases).

- Skipped examination: A special fast-track activity that bypasses additional checks and moves straight to signing; used in 332 cases.

Process metrics and performance characteristics (from DFG/variants)
- High-frequency backbone: Request -> Set Appointment -> Hand In -> Verify occurs 9,038 times with long wait between request and appointment (~82,658) and between appointment and hand-in (~82,659).
- Early rejection at Verify: 1,624 cases, faster than underwriter outcomes (~32,266 from Verify to Rejected).
- Submit -> Denied: 4,787 cases; Submit -> Sign: 2,295 cases. This indicates more denials than approvals after submitting to underwriting.
- Straight-through approval via skipped_examination: 332 cases.
- Enrichment options: Request Co-Signer (1,233) and Make Visit (1,226 initial edges), with Make Visit repeat frequency 563.
- End-to-end performance (examples from Abstract Variants):

Key challenges and pain points
- High post-submission denial rate: Many cases proceed through enrichment and submission only to be denied (4,787), causing significant waste.
- Appointment delays: The time from Request to Set Appointment and then to Hand In is long (~82k between each step), likely driving long cycle times.
- Unbounded collateral visit loops: Repeated Make Visit cycles (563 repeat edges, and long chains in variants) create rework and unpredictability.
- Inconsistent enrichment sequencing: Co-signer requests and collateral visits interleave without explicit criteria, leading to back-and-forth and additional delay.
- Skipped examination path: While fast, it bypasses checks; governance and criteria for its use are unclear.
- Modeling-induced concurrency: The technical parallel split after Verify leads to interleavings that can obscure the intended business sequence and complicate monitoring.
