# AS-IS Process Model

## Process Overview and Purpose
The process captures the steps involved in handling loan applications, including the appointment setup, the submission of required documents, and the review and decision-making phases. It reveals various potential paths applicants can take through the process, highlighting areas where applications may be denied, require additional documentation, or lead to an approval.

## Key Stakeholders and Roles Involved
- **Applicant**: Engages in the initial request and subsequent actions related to the loan application.
- **Loan Officer**: Responsible for verifying borrower information, setting appointments, and processing applications.
- **Underwriter**: Reviews submitted files and makes decisions on loan approvals.
- **Co-Signer**: May be requested in certain circumstances to support the loan application.

## Detailed Step-by-Step Process Flow

### Start Conditions and Triggers
- The process initiates when the **Applicant** requests an appointment to discuss a loan application.

### Process Activities/Tasks
1. **Request Appointment**: The Applicant requests an appointment.
   - If denial is encountered, proceed to **Appointment Denied**.
2. **Set Appointment**: The Loan Officer sets the appointment with the Applicant.
3. **Hand In Credit Application**: The Applicant submits the credit application.
4. **Verify Borrowers Information**: The Loan Officer verifies the submitted information.
5. **Decision Point - Application Outcome**:
   - Outcomes:
     - **Submit File to Underwriter**: The application file is submitted for further review.
     - **Application Rejected**: If the application cannot continue due to missing or invalid information.
     - **Loan Denied**: If the application is assessed as not meeting lending criteria.
     - **Request Co-Signer On Loan**: If additional security is needed, prompting a request for a co-signer.
     - **Make Visit to Assess Collateral**: Potential requirement to assess collateral related to the loan.

6. **Submit File to Underwriter**:
   - **Decision by Underwriter**:
     - Loan application can be accepted leading to **Sign Loan Agreement**.
     - Loan can be denied given certain conditions leading to **Loan Denied**.

7. **Sign Loan Agreement**: Finalize the loan approval process by signing the agreement.

### Decision Points with Criteria and Possible Outcomes
- **Decision 1** (After Verifying Borrower's Information):
  - If individual's information is satisfactory:
    - Move to **Submit File to Underwriter**.
  - If application details are inadequate:
    - Move to **Application Rejected**.
  - If additional security is required:
    - Proceed to **Request Co-Signer On Loan**.
  - If collateral assessment is needed:
    - Go to **Make Visit to Assess Collateral**.
  
### Parallel Activities and Synchronization Points
- Activities such as **Request Co-Signer On Loan** and **Make Visit to Assess Collateral** can occur in parallel after verifying borrower information, allowing the application to proceed through either or both pathways.

### Exception Handling and Error Paths
- **Appointment Denied** can occur directly from the **Request Appointment** and requires additional follow-up steps to resolve denial instances.
- If loan application is denied, the process flows to **Loan Denied** at the sink.

### Rework Loops and Escalation Procedures
- Instances can lead back to steps such as verifying information, especially if there are deficiencies noted during the underwriter review or collateral assessment.

### End Conditions and Outcomes
- The end can reflect multiple outcomes:
  - **Application Rejected**: The process terminates without loan approval.
  - **Loan Denied**: Concludes the application negatively.
  - **Loan Agreement Signed**: Successful completion of the process.

## Process Metrics and Performance Characteristics
- Frequency and performance metrics for each variant provide insight into the common paths taken, with numerous iterations leading through both successful and denied applications.
- The most frequent pathways range from setting appointments to finalizing loans with significant metrics tied to each step.

## Key Challenges and Pain Points Observed in the Current Process
- Frequent **Appointment Denied** situations indicating challenges in initial scheduling.
- Variability in outcomes from the application review leading to inconsistencies in applicant experiences.
- Rework loops from denial of applications or need for additional documentation suggest inefficiencies in the verification and approval processes.
- The necessity for both co-signers and collateral assessments add complexity and potential delays in the loan approval process. 

This AS-IS process model provides a comprehensive landscape of current operational behavior, capturing all potential paths and outcomes observed, reflecting both the strengths and challenges within the existing workflow.
